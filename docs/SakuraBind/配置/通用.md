# 通用

SakuraBind 的配置文件使用 YAML，后缀为 `.yml`。多数配置保存后可以自动重载；写明“重启生效”的项目仍需要重启服务端。

## 基本规则

| 规则 | 建议 |
| --- | --- |
| 缩进 | 统一使用两个空格，不要使用 Tab |
| 布尔值 | 使用 `true` / `false`，不要写中文 |
| 正则和颜色代码 | 建议加引号，避免冒号、反斜杠被 YAML 误解析 |
| 文件位置 | 修改 `服务端根目录/plugins/SakuraBind` 中的运行配置 |

<details>
<summary>常见 YAML 写法</summary>

列表写法：

```yaml
send-back-queue:
- player
- ender-chest
- database
```

层级写法：

```yaml
item-deny:
  drop: true
  click@: true
```

字符串中有特殊符号、正则表达式、颜色代码时，建议加引号：

```yaml
name-without-color: '.*传说.*'
material: '.*_SWORD'
temp-chest-title: '&a{0} 的暂存箱'
```

</details>

:::warning[容易踩坑]

不要用 OP 账号测试自动绑定。OP 默认拥有 `sakurabind.bypass.all`，会跳过自动绑定监听和扫描器。

:::

## 重载与重启

此时你可以通过命令 `/sakurabind reload` 重载全部配置，或用 `/sakurabind reload <file>` 只重载某个配置文件。

部分配置修改后需要重启，例如监听器开关、模块总开关、日志文件路径和缓存大小。具体以配置注释中的“重启生效”为准。

| 改动类型 | 建议 |
| --- | --- |
| `settings.yml` 匹配器 | `/sakurabind reload settings.yml` |
| `global-setting.yml` 行为规则 | `/sakurabind reload global-setting.yml` |
| `lang.yml` 消息文本 | `/sakurabind reload lang.yml` |
| `block-listener` / `entity-listener` | 重启 |
| 数据库类型、地址、表前缀 | 重启 |
| 模块总开关、日志路径、缓存大小 | 优先重启 |

## 修改配置的推荐流程

1. 关闭或暂停会频繁触发的功能，例如迁移模块。
2. 修改一个文件，不要一次改太多。
3. 保存后执行 `/sakurabind reload <文件名>`。
4. 用 `/sakurabind test tryMatch <匹配器ID>` 或实际物品测试。
5. 确认无误后再继续改下一个文件。

大型服建议先在测试服验证自动绑定、唯一物品、数据迁移这类会批量处理物品的功能。
