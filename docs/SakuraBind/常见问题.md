# 常见问题

## 怎么自动绑定某类物品？

在 `settings.yml` 中配置匹配器，并在该匹配器的 `settings.auto-bind` 中开启触发项。

```yaml
matchers:
  swords:
    match:
      material: '.*_SWORD'
    settings:
      auto-bind:
        enable: true
        onClick: true
        onScanner: true
```

不建议在 `global-setting.yml` 全局开启 `auto-bind.enable`，否则可能绑定大量普通物品。

## 怎么让单个物品自动绑定？

手持物品执行：

```text
/sakurabind autoBind
```

该命令会写入 `config.yml` 中 `auto-bind-nbt` 指定的 NBT。之后该物品可在扫描、点击、捡起、丢弃、使用、左右键、装备穿戴等自动绑定触发点被绑定。

## 为什么捡起别人的绑定物品没有送回？

`item.send-back-on-pickup` 只是送回行为开关，前提是对应设置中 `item-deny.pickup` 也为 `true`。

```yaml
item-deny:
  pickup: true
item:
  send-back-on-pickup: true
```

## 为什么方块或实体命令无效？

方块绑定需要 `config.yml` 开启 `block-listener` 并重启；实体绑定需要开启 `entity-listener` 并重启。实体绑定命令只在 Minecraft `1.13+` 可用。

## `/sakurabind superCallback` 会扫描离线玩家吗？

不会。它会扫描在线玩家背包、在线玩家末影箱、世界掉落物和已加载区块容器，不扫描离线玩家数据。

## 送回队列都失败会怎样？

插件会按 `send-back-queue` 依次尝试。若所有目的地都不可用或放不下，剩余物品无法继续保存，有丢失风险。建议至少保留 `database` 并保持数据库可用。

## 修改配置后为什么没生效？

先确认修改的是服务器实际运行目录：

```text
服务端根目录/plugins/SakuraBind
```

大多数配置保存后会自动重载，也可以手动执行：

```text
/sakurabind reload
```

只重载单个文件：

```text
/sakurabind reload settings.yml
```

如果配置注释写了“重启生效”，需要重启服务端，例如 `block-listener`、`entity-listener`、模块总开关、日志文件路径等。

## 物品已经绑定，为什么看不到 lore？

绑定判断依赖 NBT，不依赖 lore。下面几种情况都可能没有 lore：

- 命令绑定时使用了 `-noLore`。
- `item.lore` 配置为空。
- 其他插件修改了物品 lore。
- 物品 NBT 仍在，但绑定 lore 被手动删掉。

可以用 PlaceholderAPI 或 `/sakurabind nbt` 辅助确认物品是否仍有绑定 NBT。

## 怎么知道某个物品命中了哪个设置？

手持物品执行：

```text
/sakurabind test match
```

它会输出物品最终命中的设置名和耗时。

如果要检查某个指定匹配器为什么没命中：

```text
/sakurabind test tryMatch <匹配器ID>
```

## 玩家领不到暂存箱物品怎么办？

检查顺序：

1. `database.yml` 是否连接成功。
2. `config.yml` 是否 `send-back-database: true`。
3. 玩家背包是否有空间。
4. 玩家是否正在数据同步保护中。
5. 是否有控制台数据库报错。

管理员可以打开暂存箱查看：

```text
/sakurabind openLost <玩家名或UUID> 1
```

## 为什么绑定道具没有反应？

检查：

- `modules/bind-item.yml` 是否 `enable: true`。
- 修改模块总开关后是否重启。
- 道具是否写入了正确 NBT。
- 触发方式是否正确：把道具放在鼠标指针上，点击目标物品。
- 如果是概率配置，`75%` 应写 `75` 或 `75.0`，不是 `0.75`。

## 为什么权限覆盖配置没生效？

检查 `config.yml`：

```yaml
enable-setting-permission-check: true
```

然后确认权限节点不包含 `@`。例如配置是：

```yaml
item-deny:
  drop@: true
```

权限应写：

```text
sakurabind.settings.item-deny.drop.false
```

权限覆盖的是最终布尔值，不使用 `@`。
